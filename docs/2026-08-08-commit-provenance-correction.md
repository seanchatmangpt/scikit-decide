37 files, 3146 insertions. The SimpleGreedy agent noticed and reported it:
its changes were "not in a commit I authored or reviewed, and that commit's
message does not describe them." It was right to flag it.

## Why it matters here specifically

This repo's whole Level 4 argument is that a claim must be traceable to the
evidence that established it. A commit message that misattributes its own
contents is the same defect one layer up — the record and the reality drift
apart, and a later reader reconstructing *why* a change was made gets a wrong
answer with no indication anything is wrong.

`git add -A` under concurrency is the mechanism. Staging by explicit path is
the fix.

## Corrections applied

1. This file, recording the real contents and authorship of `f83c8a0`.
2. `openevolve_output/` and siblings added to `.gitignore` and removed from
   tracking (`git rm --cached`, 31 files). They are regenerated by every run —
   build output, never source. They were never intentionally committed.

## What is NOT changed

The code itself is correct and tested, and stays. Specifically:

- **SimpleGreedy**: the `'frozenset' object has no attribute 'facts'` failure
  was already fixed at `837cbaa`. Root cause, confirmed by real execution
  rather than inspection: a **double autocast**, not a state-shape assumption.
  `Solver.__init__` already wraps the factory's domain via
  `cast_domain_factory`; `SimpleGreedy` wrapped the same methods again. Under
  `SingleAgent` the `(Memory, Union)` rule is `obj[0]`, so the first cast turns
  `Memory([State(facts=…)])` into `State` and the second turns `State` — a
  `NamedTuple`, therefore a sequence — into its first field, the bare
  `frozenset`. Silent no-op for non-sequence states; destructive for a
  `NamedTuple` state. 3 Chicago tests pass; pyright clean.
- **Federation constructibility**: `check_domain()` applicability and
  constructor-constructibility are different facts, now reported separately.
